# FORM — 3D Dance Learning Studio

로컬 댄스 영상을 실제로 분석하고, 원본 영상과 추정 3D 동작을 함께 보는 브라우저 연습실입니다. 영상과 탭 녹화본은 FORM 서버로 전송하지 않습니다. 링크 임베드나 영상 URL을 열면 해당 제공자와는 통신합니다. 가짜 동작이나 미리 만든 분석 결과를 사용하지 않습니다.

## 실행

Node.js **24 이상**과 최신 Chrome 또는 Edge를 권장합니다.

```sh
npm ci
npm run assets
npm run dev
```

`npm ci`가 같은 버전의 MediaPipe WASM과 클래식 분석 워커를 생성합니다. Lite / Full 모델은 저장소에 포함되어 있어 `npm run assets`는 보통 체크섬 검증만 수행합니다. 모델이 없으면 Google의 버전 1 모델을 다운로드합니다. 모든 실행 자산은 같은 사이트에서 제공하며 CDN / API 키 / GPU 서버가 필요하지 않습니다.

```sh
npm test           # 좌표, 보간, 미러, 구간 반복, 데이터 검증, 실제 스킨 리그
npm run build      # TypeScript 검사 + 프로덕션 빌드
npm run preview    # 빌드 미리보기
```

## 사용

1. 처리 권한이 있는 영상을 가져오거나 원본 뷰에 놓습니다. **링크로 분석**에서는 MP4·WebM 직접 주소를 자동 분석합니다. 유튜브·숏츠·릴스는 내 PC에서 `npm run helper`(yt-dlp·ffmpeg 필요)를 켜 두면 **링크로 자동 분석**으로 받아서 바로 분석하고, 헬퍼가 없으면 원본 영상 탭을 공유해 선택 영역을 녹화한 뒤 자동 분석합니다. 로그인이 필요한 영상은 `FORM_HELPER_COOKIES_FROM=chrome npm run helper`처럼 실행하세요. 자세한 내용은 [링크 분석 문서](docs/link-analysis.md)를 보세요. 탭 공유는 데스크톱 Chrome·Edge에서 브라우저 권한 선택이 필요합니다. 원본 탭 재생은 녹화 후 직접 멈춰 주세요. **한 명의 전신**이 보이는 밝은 클립을 사용하세요.
2. 로컬 파일은 **동작 분석 시작**을 누릅니다. 링크 가져오기는 자동으로 분석을 시작합니다. 설정에서 Lite / Full, 15 / 24 / 30 fps, 흔들림 보정을 선택할 수 있습니다. 취소 버튼은 분석 워커를 종료합니다.
3. 스켈레톤 / 마네킹을 전환하고 정면, 후면, 양 측면, ¾, 자유 궤도에서 관찰합니다. 드래그 회전, 휠 / 핀치 확대, 두 손가락 이동을 지원합니다.
4. 미러, 재생 속도, 프레임 이동, A–B 반복을 사용합니다. A / B 버튼은 현재 시간을 지정하고 숫자 필드는 경계를 조절합니다. 구간에 이름을 붙여 여러 개 저장할 수 있습니다.
5. 설정에서 BPM과 첫 박자 시간을 **직접** 지정합니다. 카운트 숫자로 이동하거나 현재 8카운트만 반복할 수 있습니다.
6. 일시정지 후 스켈레톤의 관절을 누르거나 설정에서 관절을 선택합니다. 낮은 가시성 / 보간 관절은 황갈색으로 표시합니다.
7. 설정에서 모션 JSON을 내보내거나 가져올 수 있습니다. 가져오려면 먼저 일치하는 원본 영상을 선택해야 합니다. 원본 영상 자체를 서버에 저장하지 않습니다. 탭 공유 클립은 세션 중 기기 메모리에서 사용합니다. 나중에 다시 열려면 **탭 클립 저장**과 모션 JSON을 함께 보관하세요.

단축키: `Space` 재생 / 정지, `←` / `→` 1/30초 이동, `Shift` + 방향키 1초 이동, `M` 미러, `L` 구간 반복. 입력 필드에서는 단축키가 작동하지 않습니다.

## 구현 범위

- 실제 `@mediapipe/tasks-vision` Pose Landmarker, VIDEO 모드, 증가하는 프레임 타임스탬프.
- 별도 영상 디코더와 **Web Worker** 추론. OffscreenCanvas / 워커가 불가능한 브라우저는 프레임마다 이벤트 루프에 제어를 돌려주는 호환 모드로 전환합니다.
- 원본 2D / hip-relative world 랜드마크, 가시성, 존재 신뢰도, 크기, 타임스탬프 보존.
- 짧은 누락 보간, 관절별 신뢰도 처리, 빠른 동작에 반응하는 One Euro 필터, 중앙값 뼈 길이 정규화, 큰 관절 점프 거부.
- 실제 3D 스켈레톤 및 자체 제작 **21본 `SkinnedMesh` 마네킹**. 외부 캐릭터 자산 없음. 어깨·골반·몸통 비율도 클립에서 보정합니다.
- 영상의 `currentTime`만 따르는 동기 재생. 탐색, 속도 변경, 반복, 일시정지가 모두 같은 시간을 사용합니다.
- 신뢰도·영상 속도에 따른 발 접지 추정, 골반 높이 보정, 두 관절 IK, 무릎·팔꿈치 접힘 제한. 보정 전후를 재분석 없이 비교할 수 있습니다.
- 직접 영상 URL 가져오기와 명시적 브라우저 탭 공유 기반 링크 분석. 임베드만 연결하고 분석했다고 표시하지 않습니다.
- 미러를 화면에 한 번만 적용. 해부학적 좌우와 원본 관측 데이터는 유지합니다.
- 정사영 / 원근, 제자리 / 추정 이동, 분할 / 영상 / 3D 집중 보기, 모바일 세로 구성.
- IndexedDB 분석 캐시 및 삭제, 로컬 연습 구간 보존, 검증된 JSON 입출력.
- 10분 / 18,000 분석 프레임 / 180MB JSON 제한, URL / 워커 / 모델 / GPU 자원 정리.

## 정확도와 남은 한계

**제품 기능은 구현되어 있지만 정밀 모션 캡처 대체재는 아닙니다.** 단일 카메라는 가려진 관절, 깊이, 몸의 축 회전, 전역 이동을 정확히 관측하지 못합니다.

- 0.2초를 넘는 관절 누락은 보간하지 않습니다. 여러 인물이 감지되면 해당 프레임을 제외하며 인물 ID를 추정해 이어 붙이지 않습니다. 2인 검출 한도이므로 완전한 군중 / 인물 수 판별은 제공하지 않습니다.
- 3D 깊이와 추정 이동은 근사치입니다. 제자리 모드는 골반 위치를 고정합니다. 추정 이동은 화면상 골반 위치와 겉보기 크기 변화에서 얻는 휴리스틱이며 카메라 이동과 구별할 수 없습니다.
- 마네킹은 T-pose 보정, 본별 방향 / 부모 상대 쿼터니언, 고정 길이, 스킨 가중치를 갖습니다. 어깨·골반 너비와 몸통 길이는 클립 중앙값으로 보정합니다. 팔·다리 방향은 재현하지만 축 비틀림, 손가락, 세밀한 얼굴 / 머리 회전, 물리 역학은 제공하지 않습니다. 넓은 관절각 제약과 접지 IK는 구현했지만 가려진 관절 방향이나 정확한 축 회전까지 복원하지 못합니다. 불확실한 경우 원래 관측 스켈레톤을 기준으로 확인하세요.
- 보간은 타임스탬프에 따른 관절 위치 및 리그 쿼터니언 보간입니다. 뒤로 탐색해도 같은 결과가 나옵니다. 분석 지연이 안무 시간을 이동시키지 않습니다.
- HTML video에서 원본 프레임률을 신뢰성 있게 얻지 못하므로 프레임 버튼은 **1/30초** 이동입니다. 영상은 `requestVideoFrameCallback`을 사용할 수 있으면 사용합니다. 정확한 압축 프레임 인덱스 탐색은 제공하지 않습니다.
- 밝기 / 블러를 별도로 측정하지 않으며 낮은 가시성과 추적 실패로 안내합니다. 수치 정확도 점수를 만들지 않습니다.
- 한 브라우저에 저장한 구간은 다른 기기에 자동 동기화되지 않습니다. 장시간 / 4K 영상은 메모리와 디코딩 비용이 큽니다. 짧은 연습 구간을 권장합니다.
- Safari / Firefox 및 실제 iOS / Android 기기 검증은 남아 있습니다. 호환 추론은 한 프레임 동안 UI를 잠깐 점유할 수 있습니다. 서버 백엔드, 자동 비트 감지, 그룹 추적은 제공하지 않습니다. 플랫폼 링크 자동 다운로드는 내 PC에서 실행하는 로컬 헬퍼(`npm run helper`)로만 동작하며 호스팅된 앱 자체에는 다운로더가 없습니다. 헬퍼가 없으면 재생 탭을 직접 선택해 공유하는 방식을 씁니다.

실제 영상 기반 브라우저 회귀 검사는 `FORM_TEST_VIDEO=/path/to/video.mp4 npm run test:browser`로 실행합니다. 먼저 `npx playwright install chromium`을 실행하세요.

검증 범위와 미검증 항목은 [검증 기록](docs/validation.md)에 정리했습니다.

## GitHub Pages

`.github/workflows/ci-pages.yml`은 push / PR마다 테스트와 빌드를 실행합니다. Pages가 준비되어 있으면 `main` push에서 자동 배포합니다.

최초 한 번 **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택한 뒤 **Actions → Validate and deploy FORM → Run workflow**를 실행하세요. Pages 설정 전에는 검증과 아티팩트 업로드를 정상 완료하고 배포만 건너뜁니다. 별도 토큰이 필요하지 않습니다. Pages 주소는 실제 배포 작업 결과를 확인하세요.

Vite는 GitHub Actions에서 `/mirror/` 경로를 사용합니다. 저장소 이름을 변경하면 `vite.config.ts`의 base도 변경하세요. 다른 정적 호스트에는 로컬 `npm run build` 결과인 `dist/`를 배포할 수 있습니다.
